# 作業日誌を書く

フォーマットと「書かないこと」は `docs/journal/README.md` に従う。書く前に必ず読むこと。

## 手順

1. 日付を取る: `TZ=Asia/Tokyo date +%F`
2. `docs/journal/<日付>.md` を確認する
   - なければ新規作成し、`# <日付>` と `## セッション1` から書く
   - あれば既存の内容を読み、末尾に `## セッションN`（N は次の番号）を追記する。既存のセッションは書き換えない
3. 材料を集める
   - この会話でやったこと・ユーザーから聞いたこと
   - `git status` と `git log --since=midnight --oneline`
   - 前回の日誌の「次にやること」: 済んだものは今回の「やったこと」に書き、残ったものは今回の「次にやること」に引き継ぐ
4. 書く
   - 管理画面の変更は「どこを・何から何へ」まで書く
   - 事実と推測を分ける。確認していないことには `要確認:` を付ける
   - 「次にやること」は優先度順。次回のセッションはここから始まる
5. 関連ドキュメントを更新する
   - 決定事項 → `docs/decisions.md`
   - 完了したタスク → `docs/roadmap.md` のチェックボックス、`README.md` のステータス表
   - 管理画面の設定変更 → 対応する docs（auto-reply.md, rich-menu.md, line-account.md など）
6. 書いた内容の要点をユーザーに短く伝える。**commit はユーザーに言われたときだけ行う**

## 書かないこと（要約）

リポジトリは公開されている可能性がある。個人情報、認証情報、ヒアリングで出た機微な話は書かない。
迷ったら書かずにユーザーに確認する。
