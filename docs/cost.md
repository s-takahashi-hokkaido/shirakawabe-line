# 料金プランと通数課金

> 要確認:料金体系は改定されうる。着手時にLINE公式サイトで最新情報を確認すること。

## 1. プラン

| プラン | 月額 | 無料メッセージ通数 | 超過分 |
|---|---|---|---|
| コミュニケーション | 0円 | 200通/月 | 追加不可 |
| ライト | 5,000円 | 5,000通/月 | 追加不可 |
| スタンダード | 15,000円 | 30,000通/月 | 約3円/通 |

**プランの違いは基本的に「push配信の通数」だけで、機能差はほぼない。**
無料プランでもリッチメニュー、リッチメッセージ、あいさつメッセージ、
キーワード自動応答、URLリンク、1:1チャットはフルに使える。

→ **Phase 0 が無料で成立する根拠。**

プラン変更は月単位。アップグレードは即時、ダウングレードは翌月適用。
選挙月だけスタンダードに上げて終わったら下げる運用が現実的。

## 2. 通数のカウント:push と reply の非対称性

**本プロジェクトの設計上もっとも重要な区別。**

| 課金される（push） | 課金されない（reply） |
|---|---|
| 一斉配信 | **応答メッセージ（キーワード自動応答）** |
| セグメント配信 | **あいさつメッセージ** |
| ステップ配信 | **リッチメニュー経由の応答** |
| Messaging API の push message | **1:1チャットの手動返信** |
| | **Messaging API の reply message** |
| | **LINE VOOM への投稿** |

- カウント式:**友だち数 × 配信回数**
- 1回の配信で吹き出し3つまでが1通換算

### 設計上の帰結

リッチメニューのタップアクションに「テキスト」を選ぶと、
ユーザーが代わりにそのテキストを送信したことになる。
そこに自動応答を紐づけると:

```
「政策」ボタンをタップ
  → ユーザーが「政策」と送信したことになる
  → 自動応答が政策を返す
  → 通数消費ゼロ
```

**URLで外部サイトに飛ばすより、LINE内で完結させた方が離脱が少なく、しかも無料。**

## 3. コスト試算

| 友だち数 | 月4回配信 | 必要プラン | 月額 |
|---|---|---|---|
| 200人 | 800通 | ライト | 5,000円 |
| 1,000人 | 4,000通 | ライト | 5,000円 |
| 3,000人 | 12,000通 | スタンダード | 15,000円 |
| 5,000人 | 20,000通 | スタンダード | 15,000円 |
| 5,000人（選挙期間・月10回） | 50,000通 | スタンダード + 従量2万通 | 約75,000円 |

**開発側インフラ（Messaging API、Cloudflare Workers、LIFF）はほぼ無料枠に収まる。
コストの実体はLINEのプラン代。**

---

## 4. 実装時のルール

- 新しい通知機能を提案・実装するときは、**まず reply で代替できないか検討する**
- push を使う実装には、コード中に理由と想定通数をコメントで残す
- Phase 1 以降、**配信前に通数と概算コストを表示する**機能を優先度高めで入れる
