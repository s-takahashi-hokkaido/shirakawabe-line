## 標準機能でできること / できないこと

**この線引きが Phase 1 の着手判断そのもの。**

### 標準機能でできる（コード不要）

- あいさつメッセージ
- キーワード自動応答
- リッチメニュー（表示期間での切り替えを含む）
- 一斉配信 / ステップ配信
- 1:1チャット
- カードタイプメッセージ（複数画像のカルーセル）
- 友だち追加QR / URLの発行、ある程度の経路分析
- 属性（年代・性別・地域）でのセグメント配信
  ※認証済アカウント + 友だち数が一定以上という条件付き（要確認）

### 標準機能では届かない（コードの出番）

| 機能 | なぜ必要か |
|---|---|
| **流入経路の詳細トラッキング** | どのチラシ・どの街頭・どの会合から何人来たかを自分の粒度で測る。**最優先** |
| **問い合わせの外部転送**（Slack / メール） | 返信漏れの検知 |
| **キーワード揺れに強い応答** | 標準は完全一致・部分一致ベースで融通が利かない |
| LIFFフォーム（支援者登録・ボランティア応募） | 属性の取得とタグ付け |
| 回答に応じた自動タグ付け | 関心テーマ別のセグメント配信 |
| 外部データ連携（カレンダー → 予定配信） | 更新の手間の削減 |
| 配信前の通数・コスト試算 | 予算管理 |

## Phase 1:Messaging API 導入

**着手条件:標準の分析機能では流入経路が判別できなくなったとき。**

1. **流入経路トラッキング** — パラメータ付き友だち追加URL + follow イベントの記録
2. **Webhook 基盤** — 署名検証、即時200レスポンス、監査ログ
3. **問い合わせ通知** — 受信メッセージの Slack / メール転送

### 技術構成

- TypeScript / Hono on Cloudflare Workers / D1

## Phase 2:LIFF とセグメント

- 支援者登録フォーム（氏名 / 居住地区 / 年代 / 関心テーマ / 手伝えること）
- 回答に基づく自動タグ付け
- 地区別・関心別のセグメント配信
- ボランティア募集とシフト管理
- イベント・ミニ集会の出欠受付
- アンケート・意見募集

**18歳未満の選挙運動は禁止のため、ボランティア募集フォームには年齢確認を必ず入れる。**
