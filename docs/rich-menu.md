# リッチメニュー

## 1. 仕組み

リッチメニューは **「1枚の画像」+「透明なタップ領域の枠」** という構造。

```
[ 1枚の画像 ]  ←  見た目。区切り線もアイコンも文字も、全部この中に描く
     +
[ A B C D E F ]  ←  透明なグリッド。「どこを押したら何が起きるか」だけを定義
```

**枠ごとに画像を差し込む仕組みではない。**
画像側で分割デザインを描き、その区切りとグリッドを一致させる必要がある。

## 2. 仕様

| 項目 | 内容 |
|---|---|
| 画像サイズ（大） | 2500 × 1686 px |
| 画像サイズ（小） | 2500 × 843 px |
| 形式 | JPG / JPEG / PNG |
| ファイルサイズ | **10MB以下**（スマホアプリの表示による） |
| タップ領域 | 管理画面のテンプレートで最大6分割（小サイズは3分割）。Messaging API 経由なら最大20領域の自由な矩形 |

> 要確認:Messaging API 経由でリッチメニュー画像を設定する場合、
> 別のファイルサイズ上限がある。Phase 1 で触るときに確認する。

### 6分割（3×2）の1マスの寸法

| | 幅 | 高さ |
|---|---|---|
| 1マス | 約 833 px | 843 px |

デザイン時にこの位置でガイドを引けばグリッドとズレない。

## 3. 作り方

**Canva または Figma で 2500×1686 を1枚作って書き出すのが最も確実。**
Canva には「LINE リッチメニュー」のテンプレートが多数ある。

手順:
1. Canva / Figma で 2500×1686 のデザインを作成（6分割のガイドに沿って）
2. PNG で書き出し
3. 管理画面で「テンプレートを選択」→ 同じ分割比率を選ぶ
4. 「画像をアップロード」
5. 各領域にアクションを設定

> Web管理画面(PC)には枠ごとに画像・テキストを配置できる簡易エディタがあるはず（要確認）。
> あれば手早いが、仕上がりはデザインツールで作った方がきれい。

## 4. 「1枚しか使えない」の回避策

| 方法 | できること | 管理画面のみで可能か |
|---|---|---|
| **表示期間で切り替え** | 平常時メニューと選挙期間メニューを日付で自動切替 | ○ |
| **カードタイプメッセージ** | 複数画像のカルーセル（配信用。メニューではない） | ○ |
| メニューのタブ切替 | タップでメニュー自体が別の面に切り替わる | × Messaging API 側の機能。要確認 |
| 人によって違うメニュー | 支援者と一般で出し分け | × API必須（Phase 2） |

Phase 0 では「表示期間で切り替え」で十分。

## 5. 構成案（6分割・2500×1686）

| | | |
|---|---|---|
| はじめまして<br>(プロフィール) | 政策 | 活動報告 |
| 予定・街頭演説 | よくある質問 | お問い合わせ |

### アクション設定

| ブロック | アクション | 理由 |
|---|---|---|
| はじめまして | URL（既存サイト） | 詳細な情報は既存サイトに任せる |
| **政策** | **テキスト** | 自動応答で返す → 通数ゼロ |
| 活動報告 | URL（ブログ / SNS） | 更新頻度が高いものは外部に任せる |
| 予定・街頭演説 | URL または テキスト | Phase 1 でカレンダー連動を検討 |
| **よくある質問** | **テキスト** | 自動応答で返す → 通数ゼロ |
| お問い合わせ | テキスト | 受付メッセージを返し、1:1チャットに誘導 |

**「テキスト」アクションが reply中心設計の要。** → [cost.md](cost.md)

## 6. 注意

- リッチメニューは初期表示ONにすると画面の約半分を占める。**最初の印象を決める最重要パーツ。**
- リッチメニューを編集すると、関連する分析とオーディエンスの集計対象が変わる場合がある
  （管理画面に警告表示あり）
